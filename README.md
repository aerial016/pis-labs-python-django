# Прикладные информационные системы — лабораторные 1–5 и 7

Работы выполнены по разделам 1–5 и 7 методички `laby_python3.docx`.
Используются Python 3.12.10 и Django 5.2.17.
Данные студентов, пользователей и статей — учебные примеры.

## Запуск готового архива работ 1–3 на Windows

Распакуйте весь архив в папку с названием латиницей. Python и Django уже включены.

| Работа | Запуск | Адрес |
|---|---|---|
| 1: Hello world | `RUN_HELLOWORLD.cmd` | Вывод в консоль |
| 1: фильтрация студентов | `RUN_MYGROUP.cmd` | Введите порог среднего балла |
| 1: административное приложение | `START_LAB1.cmd` | http://127.0.0.1:8761/admin/ |
| 2: web-страница | `START_LAB2.cmd` | http://127.0.0.1:8762/ |
| 3: архив статей | `START_LAB3.cmd` | http://127.0.0.1:8763/ |

Админка второй и третьей работ доступна по `/admin/`.
Логин и пароль находятся в `accounts.txt` внутри папки соответствующего проекта.
Для остановки сервера нажмите Ctrl+C в его окне.
Использованы порты 8761–8763: при проверке порт 8000 на этом компьютере был недоступен.

## Лабораторная 1

`lab1/helloworld.py` выводит `Hello world!`.
В `lab1/mygroup.py` задан список `groupmates` из семи студентов с именем, фамилией,
экзаменами и оценками. Функция `filter_students` выбирает средний балл строго выше
введённого с клавиатуры порога; `print_students` выводит результат таблицей.
При пороге 4 выводятся Кирилл Смирнов, Анна Соколова и Дмитрий Попов; при пороге 5 — ни один студент.

Проект `lab1/project_name` использует базу `db_project_name`; миграции применены.
Создан первоначальный суперпользователь `labadmin`.
Через административное приложение созданы `secondadmin` с правами суперпользователя
и `student` без этих прав; у `student` снята отметка «Активный».
Эти действия сохранены в базе и журнале административного приложения.

## Лабораторная 2

Проект `lab2/firstwebpage`, приложение `flatpages`, база `db_firstwebpage`.
Адрес `/hello/` возвращает `Привет, Мир!`.
В `lab2/stages` сохранены последовательные этапы:
`01_text_plain`, `02_default_content_type`, `03_template_copy`.
В первом ответ имеет заголовок `Content-Type: text/plain`, во втором —
`Content-Type: text/html; charset=utf-8`. Содержимое ответа одинаковое.

Шаблон `index.html` содержит заголовки, маркированный и нумерованный списки
по четыре элемента, таблицу с границами: семь строк данных и шесть столбцов.
Заголовки списков имеют уровень h4.
В этапе `03_template_copy` файлы `index.html` и `static_handler.html` идентичны.
Последующие изменения сделаны в рабочем `static_handler.html`: подключён внешний
`index.css`, у h1 шрифт с засечками, изображение высотой 30 px,
размер h4 изменён с 14 на 18 px, ширина таблицы — 100% доступной ширины страницы.
Главная страница отображает этот окончательный шаблон.

## Лабораторная 3

Проект `lab3/blog`, приложение `articles`, база `db_blog`.
Модель `Article` содержит `title`, `author`, `text`, `created_date` с параметрами
из методички. `__unicode__` сохранён; для Python 3 добавлен `__str__`.
`get_excerpt` возвращает первые 140 символов и многоточие для длинного текста.
В административном списке отображаются заголовок, автор, отрывок и дата.

Три первоначальные статьи созданы через административное приложение.
Затем через SQLite исправлен текст статьи 1, заголовок статьи 2 и добавлена статья 4.
В `archive.html` размещены логотип и цикл вывода всех статей; представление `archive`
передаёт данные модели в шаблон. После проверки архива через SQLite добавлена статья 5.
Согласованность связи каждой статьи с автором проверена; в готовой базе пять статей.
Выполненные SQL-команды сохранены в `01_edit_and_add.sql` и `02_add_after_archive.sql`.
Повторно применять их к готовой базе не нужно.

## Лабораторная 4

Проект `lab4/blog` продолжает блог из работы 3. Приложение `articles` перенесено
в отдельный проект. Маршрут `/article/<id>/` принимает числовой идентификатор,
представление `get_article` показывает полный текст; для отсутствующей статьи — 404.
Заголовки архива ведут на страницы статей, ссылка «Все записи» возвращает в архив.
Оба шаблона используют `articles/static/css/article.css`: фон `#1abc9c`, белый текст,
логотип, автор слева и дата справа. Классы `body` — `archive` и `article`.
Оформление проверено по двум макетам из методички.

Дополнительно выполнена указанная в LMS цель этой работы — запросы на выборку
с операторами и функциями. В `lab4/queries.sql` находятся пять запросов SELECT;
`lab4/query_results.txt` содержит фактические результаты. Используются условия,
соединение таблиц, сортировка, группировка и функции строк, дат и агрегирования.
`lab4/run_queries.py` повторно выполняет запросы, открывая базу в режиме чтения.
В архиве `lab4.zip` для сдачи есть исходники, готовая база с пятью статьями,
результаты запросов и `README.txt` с инструкцией. Для запуска сайта используется порт 8764.

## Лабораторная 5

Проект `lab5/blog` содержит форму `/article/new/` и представление `create_post`.
Создание статьи доступно авторизованному пользователю. Перед сохранением проверяются
заполнение полей и уникальность названия. Автором назначается текущий пользователь;
после сохранения открывается страница новой статьи. При ошибке данные остаются в форме.
Шаблон `create_post.html` содержит CSRF-токен и подключён к общему CSS-файлу.

В `lab5/queries.sql` представлены многотабличные запросы и выборки с вложенными
запросами, включая `IN`, `EXISTS` и коррелированные подзапросы.
Результаты находятся в `lab5/query_results.txt`.
Запуск запросов: `python run_queries.py` из папки `lab5`.
Запуск сайта: `python manage.py runserver 127.0.0.1:8765` из папки `lab5/blog`.

## Лабораторная 7

Проект `lab7/blog` содержит скрипты `helloworld.js` и `fold-post.js`.
Массив студентов выводится таблицей в консоль браузера. Группа и порог среднего
балла вводятся в поля на странице; результаты фильтрации выводятся в консоль.
Средний балл отбирается строго выше введённого порога.
Кнопки статей добавляют или удаляют класс `folded` у родителя `one-post`;
CSS скрывает автора, дату и текст, а повторный клик возвращает их.

В `lab7/triggers.sql` находятся три триггера SQLite для добавления,
изменения заголовка и удаления статьи. Миграция `0002_article_triggers`
создаёт триггеры и таблицу журнала `article_changes`.
В `lab7/commands.sql` сохранены команды, в `lab7/trigger_results.txt` — результаты.
Для повторного выполнения команд: `python run_commands.py` из папки `lab7`.
Для запуска сайта: `python manage.py migrate`, затем
`python manage.py runserver 127.0.0.1:8767` из папки `lab7/blog`.

## Исходники из Git

В публичный репозиторий помещаются исходники работ. Переносимый интерпретатор,
готовые базы и файлы с паролями входят в архив для сдачи и исключены из Git.
Для запуска исходников с установленным Python 3.12:

```console
python -m pip install -r requirements.txt
cd lab3/blog
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8763
```

Для работ 1 и 2 используйте соответственно `lab1/project_name` и
`lab2/firstwebpage`; команды миграции и запуска те же.
Заполнение через административное приложение и SQLite выполняется в порядке,
описанном выше. Готовый результат с заполненными базами находится в архиве для сдачи.
